## 🎓 HACKATHON STRATEGY & TIPS

### **How to Choose Which Hackathons to Enter:**

**Priorities for First-Timers:**
1. ✅ **Online/Remote** - No travel barrier
2. ✅ **Beginner-friendly** - Look for "beginners welcome"
3. ✅ **1-2 day duration** - Manageable time commitment
4. ✅ **Clear theme** - Easier to come up with ideas
5. ✅ **Workshop support** - Learn while building

**My Top 5 Recommendations for You (Nov 18, 2025):**

1. **MLH Global Hack Week: AI/ML** (Dec 12-18) - Perfect first hackathon, beginner-friendly, week-long

### **Hackathon Preparation Checklist:**

**2 Weeks Before:**
- [ ] Register for hackathon
- [ ] Join Discord/Slack community
- [ ] Review rules and judging criteria
- [ ] Brainstorm 3-5 project ideas
- [ ] Check tech requirements
- [ ] Set up dev environment

**1 Week Before:**
- [ ] Finalize project idea
- [ ] Create tech stack plan
- [ ] Find teammates (if team event)
- [ ] Prepare boilerplate code
- [ ] Review sponsor APIs/tools
- [ ] Plan your schedule (sleep, meals)

**During Hackathon:**
- [ ] Attend opening ceremony
- [ ] Build MVP first (core features only)
- [ ] Ask mentors for help
- [ ] Document as you build
- [ ] Create demo video (most hackathons require this)
- [ ] Write clear README
- [ ] Submit early (don't wait until deadline)

**After Hackathon:**
- [ ] Share on social media (Twitter/LinkedIn)
- [ ] Add to portfolio
- [ ] Write blog post about experience
- [ ] Keep building (improve project after hackathon)
- [ ] Apply learnings to grant applications

---

### **What Makes a Winning Hackathon Project:**

**4 Key Elements:**

1. **Solves a Real Problem** ⭐⭐⭐⭐⭐
   - Don't build "cool tech"
   - Build something people NEED
   - Show the pain point clearly

2. **Works (Demo-able MVP)** ⭐⭐⭐⭐⭐
   - Functional > Feature-rich
   - Live demo > Video only
   - Show, don't tell

3. **Clear Presentation** ⭐⭐⭐⭐
   - 2-3 minute pitch
   - Problem → Solution → Demo → Impact
   - Good demo video

4. **Uses Sponsor Tech (if applicable)** ⭐⭐⭐
   - Integrate sponsor APIs
   - Mention sponsors in pitch
   - Apply for sponsor bounties

---

### **Time Management (24-Hour Hackathon):**

**Hour 0-2:** Ideation & Planning
- Finalize idea
- Design architecture
- Divide tasks (if team)

**Hour 2-16:** Building
- Focus on MVP
- Core features only
- Test as you build

**Hour 16-20:** Polish & Demo
- Bug fixes
- Demo video recording
- README + documentation

**Hour 20-24:** Submission & Buffer
- Submit project
- Prepare pitch
- Buffer time for issues

---

### **Common Mistakes to Avoid:**

1. ❌ **Scope too large** - Build less, polish more
2. ❌ **Starting too late** - Begin building immediately
3. ❌ **No sleep** - Get 4-6 hours minimum (you'll code better)
4. ❌ **Ignoring submission requirements** - Read rules carefully
5. ❌ **Poor demo** - Practice your pitch 3-5 times
6. ❌ **No README** - Judges need to understand your project
7. ❌ **Forgetting to submit** - Submit 1 hour early (servers crash at deadline)
